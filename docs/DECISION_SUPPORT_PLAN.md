# Happy House 의사결정 지원 기획안

작성일: 2026-09-09

상태: 2026-09-09 작성한 원안. 이후 사용자의 구현 위임에 따라 2026-09-10 핵심 의사결정 기능을 구현했다. 아래 진단은 개선 전 기록이며, 현재 구현 범위와 미구현 항목은 [구현 안내](DECISION_PLANNER.md)를 기준으로 확인한다.

검토 기준: 요구사항 1~74, 현재 화면과 계산/추천/동기화 코드, 원격 main의 데이터 커밋 `f2607980f61883cfb1712efcec9263dd34f036af`, 공식 데이터 제공 문서. 데이터 수집 기준 시각은 2026-09-09 18:20 KST다. 브라우저 동작을 새로 검증한 결과가 아니라 코드와 저장 데이터에 근거한 진단이다.

## 1. 제품이 도와야 하는 결정

**월 부담을 감당하면서, 현재 집을 유지하는 경우보다 자산가치와 생활 여건이 나아질 후보를 선택한다.**

추가 답변에서 사용자는 `월 부담을 관리하면서 자산가치 높이기`를 최우선으로 선택했다. 따라서 월 현금흐름을 통과 조건으로 먼저 적용하고, 이후 현재 집 유지 대비 자산 개선 가능성을 비교한다. 출퇴근은 반드시 지킬 조건과 생활비에 반영한다.

사용자는 이미 집을 보유한 갈아타기 수요자다. 따라서 매수가와 상승률만으로 추천하면 부족하다. 현재 집의 매도 순자금, 새 집까지의 추가 비용, 두 직장의 출퇴근, 거치 종료 후 부담을 함께 비교해야 한다.

핵심 질문은 다음 다섯 가지다.

1. 이 집으로 옮기면 지금보다 무엇이 좋아지고 무엇을 포기하는가?
2. 세금과 복비를 내고 비상자금까지 남긴 상태로 살 수 있는가?
3. 지금뿐 아니라 37개월차와 신용대출 만기도 감당할 수 있는가?
4. 두 사람의 출퇴근이 각각 얼마나 달라지는가?
5. 더 알아볼 후보와 실제 방문할 후보를 무엇으로 좁힐 것인가?

- 각자의 교통수단, 출근 시각, 주당 출근일, 디지털시티 출입문·셔틀 조건.
- 현재 집에서 불편한 점, 최소 면적, 연식·주차·학군의 우선순위.
- 추가 현금, 배우자 소득을 포함한 가계 월 실수령액, 생활비, 남길 비상자금.
- 현재 주담대의 금리·잔여기간, 새 사내 대출의 원금 상환 방식과 재직 조건.
- 명의, 세대 주택 수, 취득·거주 이력, 실제 매도/매수 일정.

설정 화면에서는 기존에 알려준 조건을 모두 기본값으로 유지하고, 새로운 비교에 필요한 항목만 점진적으로 받는다. 실제 근무지 답변으로 도착점은 구체화되었지만 차량·대중교통·셔틀 여부와 출근 시각은 아직 정해지지 않았다.

- 일반 후보·추천 추적은 22개 단지이며, 이 중 최신 면적별 거래가가 9~11억원에 해당하는 단지는 16곳이다. 시장 전체의 매물 수가 아니다.
- 최신 수집 시각과 거래일은 다르다. 예를 들어 SK-VIEW 124㎡는 2026-01-05의 1건이 최신 거래로 남아 있다. 이런 표본을 최근 다수 거래와 동일하게 취급하지 않아야 한다.
- 우리집 59㎡ 최신 저장 거래는 2026-08-24, 8억4,000만원, 3층이다. 이는 해당 신고 거래이며 사용자 집의 확정 매도가가 아니다.
- 재건축 사업 270개 중 실거래 매칭 성공은 32개다. 거래 없음 192개와 이름/주소 매핑 미완료 46개를 구분해야 한다.
- 서버에서 사전 검증해 저장한 재건축 좌표는 0개이며 상태는 `not_configured`다. 브라우저 좌표 보완 경로가 있으므로 이것만으로 화면의 핀 개수를 단정하지 않는다.
- 매물 공급자는 미연결이며 KB 자동 시세도 미연결이다. 기본 KB 값은 매교 SKVIEW 84.97㎡의 2026-07-17 수동 기준이므로 다른 후보에 그대로 적용하면 안 된다.
- [sync-status.json](../data/sync-status.json)은 생성되지만 현재 화면 코드에서 이 파일을 읽지 않는다. 사용자가 보는 상태와 원본별 상태를 연결할 필요가 있다.

## 4. 최우선 기능: 후보별 갈아타기 계산

사용자가 단지와 전용면적을 선택하고 예상 매수가를 입력하면, 같은 조건으로 세 가지 결과를 반환한다.

1. **필요한 추가 현금:** 매매대금과 모든 부대비용에서 실제 조달금을 뺀 금액.
2. **이사 후 남는 돈:** 비상자금 목표를 지킬 수 있는지까지 표시.
3. **월 부담:** 거치 중, 37개월차, 신용대출 만기와 그 이후를 연결.

계산의 기준:

```text
매도 순자금 = 예상 매도가 - 기존 주담대 상환 - 매도비용
사내 대출 한도 = min(5억원, 후보 매수가 × 70%, 후보 KB 평균 × 70%)
조달금 = 매도 순자금 + 사용할 현금 + 사내 대출 실행액 + 신용대출 실행액
필요자금 = 후보 매수가 + 매수세금·복비 + 등기·대출비용 + 이사·수리비
부족액 = max(0, 필요자금 + 남길 비상자금 - 조달금)
```

매도 복비는 매도 순자금에서 한 번만 차감한다. 자금 항목이 같은 비용을 두 번 빼지 않도록 총액과 지출 내역을 구분한다. 비상자금도 현금 입력에서 이미 제외했다면 다시 차감하지 않는다.

매수가를 모르는 경우에는 부족액이 0이고 월 부담 제한도 통과하는 최대 매수가를 역산한다. 이론적 대출 한도와 금융기관의 확인된 실행 가능액을 구분한다. DSR 등 실제 심사 결과를 사내제도 공식만으로 확정하지 않는다.

KB 시세는 단지·면적·기준일과 함께 저장한다. 없는 후보는 `확인 필요`로 표시하고 다른 집의 KB 값으로 확정 한도를 계산하지 않는다.

사내 지원분의 세금은 월 환산 추정과 실제 원천징수/정산 시점을 구분한다. 연봉만으로 세액이 확정된 것처럼 표시하지 않고, 급여명세 또는 확인된 세율로 보정할 수 있게 한다.

## 5. 두 사람 출퇴근 비교

평가 단위를 지역에서 **단지 출입구와 실제 직장 도착점 사이의 경로**로 바꾼다.

- 배우자와 본인의 편도시간을 각각 보여주고, 현재 집 대비 증감을 함께 표시한다.
- 도보시간, 환승 횟수, 정류장까지 거리, 주당 출근일을 반영한다.
- 본인의 차량·대중교통·사내셔틀을 구분한다. 셔틀은 사용자가 확인한 노선과 소요시간을 입력할 수 있게 한다.
- 디지털시티 중앙문과 정문을 각각 계산하고 이용 가능한 경로를 비교한다. 문까지 도착하는 시간에 실제 업무 공간까지의 이동을 별도 반영한다.
- 두 사람 각각의 최대 허용시간을 먼저 적용한다. 한 사람의 긴 통근이 평균점수에 가려지지 않게 한다.
- 합산 주간 통근시간과 더 오래 걸리는 사람의 시간을 함께 비교한다.
- 출퇴근시간 정보는 `경로 조회`, `사용자 실측`, `단순 추정`으로 구분하고 조회 시점과 수단을 표시한다.

예를 들어 편도 10분 단축은 왕복·월 22일 출근 가정에서 한 사람에게 약 7시간 20분을 돌려준다. 가격 차이와 나란히 제시하되 시간을 임의의 원화 점수로 환산하지 않는다.

지도에는 확인된 경로 기준으로 두 사람의 제한을 모두 통과한 후보를 강조한다. 거리 원을 그려 통근 가능 구역으로 간주하지 않는다.

데이터 조건: [NAVER Directions 5](https://api.ncloud-docs.com/docs/application-maps-directions5)는 실시간 교통을 반영한 자동차 경로 API다. 14시 호출 결과를 아침 출근시간으로 표시하면 안 된다. 대중교통은 [ODsay](https://lab.odsay.com/guide/releaseReference) 등 별도 연결을 검토해야 하며, [운영 안내](https://lab.odsay.com/contact/contact?act=srvc)의 호출 한도와 분석·대량 수집 조건 확인이 선행된다. 초기 버전은 관심 후보의 길찾기 링크와 수동 확인값으로도 유용하게 만든다.

| 즉시 지출 | 세금·복비·이사·수리 포함 순수 추가 현금 |
| 월 현금흐름 | 원금, 이자, 지원분 추가세금, 관리비, 보유세 월 적립액, 교통비 |
| 장기 부담 | 37개월차, 만기 원금, 남은 비상자금 |
| 주거 만족 | 주차, 연식, 관리 상태, 소음, 경사, 생활시설 등 선택한 중요 조건 |
| 가격 근거 | 최신 동일 면적 실거래 날짜·층·가격, 최근 표본 수 |
| 미확인 항목 | 매물 호가·KB·수리비·통근 실측 등 결정 전에 확인할 값 |

`월 통장에서 나가는 돈`과 `되돌아오지 않는 지출`을 구분한다. 원금 상환은 현금유출이지만 부채를 줄이는 항목이므로 이자·세금·교통비와 같은 소비비용으로 합쳐 해석하지 않는다.

현재 사용자 우선순위에 맞춰 거치 종료 후 월 부담, 만기 대응 자금, 비상자금 조건을 먼저 검사한다. 통과한 후보들에서 자산 개선 가능성과 두 사람의 통근·주거조건을 비교한다. 점수 몇 점 차이로 무조건 한 후보를 정답으로 내리지 않으며, 장단점이 갈리는 후보는 함께 남긴다. 사용자가 정하지 않은 통근 한도나 월 부담 상한을 임의로 확정하지 않는다.

면적은 최소 기준을 직접 설정한다. 49㎡의 가격과 84㎡의 가격을 같은 상품처럼 추천하지 않는다. 단지 추천에서 실제 동·층·향·수리 상태가 있는 매물 비교로 넘어갈 수 있어야 한다.

## 7. 가격 차이와 자금 위험 시나리오

갈아타기에서는 새 집 가격뿐 아니라 **새 집 가격과 현재 집 매도가의 차이**가 중요하다.

### 7.1 현재 집 유지 대비 3년·5년 순자산

사용자의 자산가치 목표를 직접 지원하는 핵심 결과다. `집값 상승률`과 `가계 순자산 증가`를 구분한다. 비싼 집으로 옮겨 집값이 더 올라도 거래비용과 이자 부담으로 저축이 줄어들면 최종 결과가 달라질 수 있다.

```text
비교시점 순자산 = 해당 시점 주택가치 - 남은 대출원금 + 누적 금융자산
갈아타기 효과 = 이사한 경우의 순자산 - 현재 집을 유지한 경우의 순자산
```

두 경우 모두 같은 시작 자산, 가계 소득·생활비, 금융자산 수익률 가정을 사용한다. 이사비·세금·복비는 발생 시점에 현금에서 차감하고, 원금 상환은 현금 감소와 부채 감소에 동시에 반영해 비용으로 중복 차감하지 않는다. 만기 원금도 부채와 현금 양쪽에 반영한다.

주택을 계속 보유하는 시점 평가와, 그때 매도했을 때의 비용·세금을 반영한 청산가치를 구분한다. 양도세 조건이 미확인이면 청산가치와 세후 수익은 미확정으로 남긴다. 미래 소득·금리·주택가치는 입력 가정이며 예측값이 아니다.

현재 집과 후보의 가격이 함께 움직이는 경우, 후보가 더 오르는 경우, 후보가 덜 오르거나 하락하는 경우를 비교한다. 후보 집만 상승시키고 현재 집은 고정하는 가정을 기본값으로 쓰지 않는다.

출력은 `현재 집 유지보다 순자산이 많아지려면 후보가 얼마 이상이어야 하는지`, `월 저축이 얼마나 달라지는지`, `불리한 가정에서도 비상자금이 남는지`다. 손익분기 가격은 사용자 가정 아래의 계산 결과로 표시한다.

현재 주담대의 금리와 잔여기간, 가계 현금·실수령·지출은 새로 확인해야 하므로, 지금의 저장 데이터만으로 순자산 유불리를 확정하지 않는다.

### 7.2 가격 차이와 스트레스 비교

- 동일 기준일 구간의 우리집과 관심 후보 가격 차이를 추적한다. 거래 시점이 크게 다르면 비교 근거 부족으로 표시한다.
- 최신 실거래를 대표 숫자로 유지하되, 최근 3~5건과 표본 수로 맥락을 제공한다. 임의로 평균가를 최신가처럼 바꾸지 않는다.
- 예산 초과 후보에는 얼마에 매수하거나 얼마에 매도해야 자금 조건을 통과하는지 보여준다. 이것은 가계 기준의 목표가격이며 시장 적정가 추정과 구분한다.
- 매도가 3,000만원 하락, 신용금리 2%p 상승, 수리비 추가, 매도잔금 지연 같은 입력 가능한 가정을 비교한다. 실제 발생 전망으로 표시하지 않는다.
- 신용대출 만기 연장은 자동 가정하지 않는다. 만기 상환을 기본으로 두고 연장 가정은 별도 시나리오로 둔다.
- 사내대출 지원 종료나 퇴직 시 조건은 확인한 계약 조항을 입력받아 계산한다. 현재 3.1% 지원이 어떤 경우에도 계속된다고 가정하지 않는다.

계약금과 잔금 날짜는 필요할 때만 세부 계산에 쓴다. 사용자가 원하지 않았던 임의의 계약 진행 상태나 이사 카운트다운을 홈에 추가하지 않는다. 실제 목적은 매도대금이 들어오기 전에 계약금이 먼저 필요할 때의 부족액 확인이다.

## 8. 후보 발굴과 현장 확인

추천 후보를 코드에 고정하는 대신, 관심 생활권의 신고 거래에서 단지 후보를 찾고 건물·단지 정보와 결합한다. 이름만으로 합치지 않고 법정동·주소·공식 식별자를 확인한다. 신규 단지의 가격이 맞으면 발견 목록에 추가하고, 현재 선택한 후보는 가격이 범위를 벗어나도 사라지지 않게 한다.

첫 단계 필터는 예산 총액, 최소 면적, 각자 통근 상한과 필수 주거조건이다. 지역은 탐색 범위이며 단지의 품질점수로 대체하지 않는다. 거래가 없는 단지는 매물 확인 대상으로 따로 보관할 수 있다.

방문 전에는 부족한 정보를 3개 정도로 좁혀준다. 방문 후에는 야간 주차, 소음, 경사, 역까지 실제 도보, 누수·수리, 채광과 같은 관찰을 짧게 남긴다. 사람별 의견과 확인 날짜를 보존하고 개인 취향을 객관적인 사실로 덮어쓰지 않는다.

공식 생활정보는 [공동주택 기본 정보제공 서비스](https://www.data.go.kr/data/15058453/openapi.do)의 단지·설비 정보를 우선 검토한다. 관리비는 [K-apt](https://www.k-apt.go.kr/) 공개 자료 및 개별 관리비 제공 범위를 추가 확인하고, 같은 전용면적의 개별 고지서와 단지 평균 추정값을 구분한다. 층간소음·주차 체감·실제 내부 상태는 현장 확인 항목으로 남긴다.

## 9. 재건축과 자산가치

재건축은 당장 살 집과 별도 비교 모드로 둔다. 거래가만 같은 예산 범위에 들어온다고 바로 입주할 일반 아파트와 동일 순위에 넣지 않는다.

비교할 금액은 매수가, 확인 가능한 추정 분담금, 이주·임시거주 비용, 이주대출 이자와 세금 등이다. 분담금과 일정의 확정 여부를 표시하고, 미확인 비용을 0원으로 처리하지 않는다.

사업 단계는 공식 인허가 문서의 일자와 원문에 연결한다. 표준적인 소요 기간은 설명 자료로 쓰되 특정 사업의 확정 준공일로 제시하지 않는다.

상승 분석은 `과거 36개월 가격 흐름`으로 명확하게 설명한다. 거래량·동일 면적 비교·최근성·인근 공급과 확인된 사업 진척을 보여주되, 이를 향후 상승률이나 확률로 바꾸려면 별도의 검증이 필요하다. 호재는 발표·승인·착공·개통 상태와 출처를 나누고 자동으로 가점을 주지 않는다.

## 10. 화면 구성

탭을 더 늘리기보다 기존 화면의 역할을 정리한다.

| 현재 화면 | 제안 역할 |
| --- | --- |
| 홈 | 지킬 수 있는 매수가 상한, 선택 후보의 월 부담, 우리집 대비 좋아지는 점. 관심 후보 최대 3곳과 중요한 변경만 노출 |
| 대출 관리 | 우리집 자금과 가계 조건, 후보별 갈아타기 계산, 월별·잔금 일정 상세 |
| 우리집 가격 | 59㎡ 실거래, 예상 매도가 범위, 후보와의 가격 차이 |
| 추천 | 새 후보 발견. 모든 추천에 같은 자금·통근·면적 기준 적용 |
| 이사 후보지 | 저장한 단지·면적·매물, 현재 집과 나란히 비교, 방문 메모 |
| 지도 | 우리집, 두 직장, 저장 후보와 재건축을 구분해 표시. 후보 선택과 비교 화면을 연동 |
| 재건축 | 사업 단계와 근거, 총투입액·지연 시나리오 중심의 별도 탐색 |

홈의 출력 예시는 `후보 A: 현재 집보다 15㎡ 넓어짐 / 두 사람 주간 통근 2시간 감소 / 37개월차 월 부담 40만원 증가`처럼 변화 세 가지로 제한한다. 이 숫자는 화면 형식 예시이며 실제 단지 계산 결과가 아니다.

모바일은 한 번에 현재 집과 후보 하나를 비교하고 고정된 전환 버튼으로 다른 후보를 선택한다. 데스크톱은 현재 집과 후보 3곳을 같은 행 기준으로 비교한다. 상세 내역은 펼쳐 보고, 기본 카드에는 가격·자금·통근과 확인할 점만 둔다.

일일 동기화가 성공했다는 사실과 데이터 내용이 최신이라는 사실을 분리한다. 수집 시각, 거래일, 원본 기준일, 마지막 정상값, 미연결 여부를 각각 저장하고 화면에는 결정에 필요한 상태만 짧게 보여준다.

정적 GitHub Pages 구조로 자금 계산·후보 비교·기기 내 저장부터 만들 수 있다. 새로 입력받는 급여·현금·정확한 출퇴근 설정·개인 메모는 공개 저장소의 데이터 파일로 보내지 않는다. 처음에는 기기 내 저장과 사용자가 선택하는 내보내기/가져오기를 제공한다. 두 사람의 자동 공유가 필요해지면 인증이 있는 별도 저장소와 화면을 후속 단계로 설계한다.

변경 알림도 처음에는 홈에서 이전 방문 이후 변경점만 보여준다. 대외 메시지 발송이나 새 알림 서비스를 전제로 하지 않는다.

| 2 | 후보 저장, 우리집 기준 비교, 156개월 현금흐름과 3년·5년 순자산 | 현재 집과 후보 3곳을 같은 조건으로 비교. 37개월차와 만기 원금이 달력에 표시됨. 가계 조건이 갖춰지면 가정별 순자산 차이와 손익분기 가격 산출. 새로고침 후 조건 유지 |

| 4 | 지역 내 후보 자동 발굴, 기본 생활정보, 방문 메모 | 등록 목록 밖에서도 필수조건에 맞는 후보 발견. 거래 없는 이유와 탈락 이유 확인. 방문 후 비교표 갱신 |
| 5 | 재건축 총투입액, 사업 근거, 가족 공유 | 미확정 분담금·기간을 포함한 시나리오 구분. 공유를 선택한 정보만 계정 간 전달 |

첫 출시 범위로는 **후보별 갈아타기 계산 + 우리집/후보 비교 + 기기 내 저장**을 권장한다. 여기에 현재 주담대와 가계 현금흐름 입력이 확보되면 같은 계산 결과로 **3년·5년 순자산 시나리오**를 연결한다. 출퇴근은 확인값 입력과 지도 링크로 먼저 시작하고, 필요한 데이터 조건이 갖춰지면 경로 자동화를 붙인다. 성공 기준은 추천 카드 수가 아니라 두 사람이 같은 근거로 방문 후보를 3곳까지 좁히고, 각 후보의 부족자금·거치 후 부담·통근 차이·현재 집 유지 대비 손익분기를 설명할 수 있는지다.
